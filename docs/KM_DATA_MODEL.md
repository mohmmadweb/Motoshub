# مدل داده، قواعد و رویدادهای ماژول مدیریت دانش

این سند برای تیم بک‌اند است و از روی پروتوتایپ نوشته شده است. منبع کد:

- `src/km/types.ts`: مدل داده
- `src/km/access.ts`: قواعد دسترسی و حل تأییدکننده‌ی هر مرحله
- `src/km/text.ts`: نرمال‌سازی جستجو و مقایسه‌ی نسخه‌ها
- `src/context/KnowledgeContext.tsx`: اکشن‌ها، لاگ و اعلان‌ها

پروتوتایپ همین منطق را در مرورگر اجرا می‌کند و داده را در `localStorage` با کلید `motoshub.km.v1` و نسخه‌ی ۲ نگه می‌دارد.

برای دیدن هر قابلیت در دمو به این مسیرها بروید:

| قابلیت | مسیر در دمو |
|---|---|
| فهرست دسترسی سند | `/dashboard/knowledge?doc=d9` ← تب «دسترسی» |
| پیش‌نمایش «فقط مشاهده» با واترمارک | همان سند ← تب «فایل‌ها و نسخه‌ها» ← «پیش‌نمایش» |
| مقاله و مقایسه‌ی متنی نسخه‌ها | `?doc=a1` |
| گردش کار معوق | `?tab=workflow`، فیلتر «معوق» |
| قالب‌های گردش کار | `?tab=settings` |
| لاگ ممیزی | `?tab=audit` |
| جستجو | `?tab=search` |

مرجع الزامات: `docs/شرح_جامع_ماژول_مدیریت_دانش_سازمانی.docx`. شماره‌ی بندهایی که در این سند می‌آید به همان سند اشاره می‌کند.

## ۱. قاعده‌ی کلی

1. هر تغییر از یک اکشن عبور می‌کند. هر اکشن دو کار انجام می‌دهد:
   - یک رکورد **لاگ ممیزی** می‌سازد (بخش ۷). لاگ تغییرناپذیر است.
   - اگر لازم باشد، **اعلان** صادر می‌کند (بخش ۸).
2. انجام‌دهنده برای کار خودش اعلان نمی‌گیرد. اگر یک نفر به چند دلیل گیرنده باشد، فقط یک اعلان برایش فرستاده می‌شود.
3. **مشاهده، پیش‌نمایش و دانلود** هم لاگ می‌شوند. سطح دسترسی سند در لحظه‌ی رویداد روی رکورد لاگ ذخیره می‌شود، چون ممیزی اسناد محرمانه به آن نیاز دارد.
4. رویدادهای زمان‌محور را یک **زمان‌بند روزانه** صادر می‌کند:
   - یادآوری بازبینی دوره‌ای
   - یادآوری مرحله‌ی معوق گردش کار
   - تشدید به مالک سند

   هر کدام با یک کلید یکتا فقط یک بار ارسال می‌شود، مثلاً `wf:{docId}:{stepIdx}:{stepStartedAt}` یا `review:{docId}:{reviewDate}`.
5. همه‌ی تاریخ‌های نمایشی شمسی‌اند. سرور تاریخ را به‌صورت ISO ذخیره کند و تبدیل به شمسی در لایه‌ی نمایش انجام شود.

### ۲-۲. فایل و نسخه

```ts
KFile    = { id, name, size, ext, text?: string, pages?: number }
KVersion = { version, date, by, note, files: KFile[], body?: string }
```

- `text` **متن استخراج‌شده** از فایل است و صفحه‌ها در آن با کاراکتر `\f` از هم جدا می‌شوند. سرور هنگام بارگذاری این متن را تولید کند و در نمایه‌ی جستجو قرار دهد:
  - PDF: با Tika یا pdftotext
  - Word: با docx2txt
  - تصویر: با OCR فارسی
- هر نسخه فایل‌ها یا `body` خودش را نگه می‌دارد. مقایسه‌ی متنی دو نسخه روی `body`، یا اگر `body` نباشد روی `text` فایل‌ها، انجام می‌شود. الگوریتم مقایسه سطربه‌سطر است: LCS در پروتوتایپ و Myers در سرور.
- ویرایش متن مقاله همیشه یک نسخه‌ی جدید می‌سازد.

### ۲-۳. فهرست کنترل دسترسی (`KAcl`)

```ts
KAcl      = { entries: KAclEntry[], viewOnly: boolean }
KAclEntry = { kind: "user" | "scope" | "role" | "title", id: string, download: boolean }
```

| `kind` | `id` | چه کسی منطبق است |
|---|---|---|
| `user` | شناسه‌ی کاربر | خودِ کاربر |
| `scope` | شناسه‌ی واحد در IAM (هلدینگ، شرکت یا واحد) | هر کسی که در این واحد یا یکی از زیرمجموعه‌هایش عضویت فعال یا نقش معتبر دارد |
| `role` | شناسه‌ی نقش در IAM | هر کسی که تخصیص معتبر این نقش را دارد |
| `title` | عنوان سمت (`Membership.title`) | هر کسی که عضویتی با این سمت دارد |

### ۲-۴. سیاست سطح دسترسی (`KSettings.accessPolicy`)

```ts
Record<AccessLevel, { download: boolean; watermark: boolean }>
```

| سطح | دانلود | واترمارک |
|---|---|---|
| عمومی | ✓ | — |
| داخلی | ✓ | — |
| محرمانه | — (فقط مشاهده) | ✓ |
| خیلی محرمانه | — (فقط مشاهده) | ✓ |

جدول بالا مقدار پیش‌فرض است و راهبر دانش آن را در «تنظیمات و دسترسی‌ها» تغییر می‌دهد.

### ۲-۵. گردش کار

```ts
KWfTemplate = { id, name, docTypes: string[], steps: KWfStep[] }      // docTypes خالی = قالب پیش‌فرض
KWfStep     = { id, name, kind: "review" | "approve" | "publish", approver: WfApprover, slaDays, substitute? }
WfApprover  = { kind: "user", id } | { kind: "role", id } | { kind: "scopeManager" } | { kind: "owner" }
KDocFlow    = { templateId, stepIdx, stepStartedAt, history: KFlowEvent[] }
KFlowEvent  = { stepId, stepName, by, decision: "submit" | "approve" | "return" | "publish" | "remind" | "escalate", at, note?, onBehalfOf? }
KDelegation = { id, from, to, until, note? }                           // جانشینی موقت
```

- هر نوع سند حداکثر به یک قالب تعلق دارد. اگر نوعی قالب اختصاصی نداشته باشد، قالب پیش‌فرض برایش استفاده می‌شود.
- قالبی که سند با آن شروع شده (`templateId`) روی خود سند ذخیره می‌شود. تغییر قالب بعدها روی گردش کار جاری آن سند اثری ندارد.

### ۲-۶. لاگ ممیزی (`KLog`)

```json
  "seq": 731,
  "at": "2026-05-29T10:12:00Z",
  "actor_id": "u5",
  "action": "پیش‌نمایش فایل را دید (فقط مشاهده)",
  "code": "preview",
  "entity": { "type": "doc", "id": "d9", "title": "تفاهم‌نامه همکاری…" },

```

- مقادیر مجاز `code`:
  `view` · `preview` · `download` · `create` · `edit` · `delete` · `version` · `workflow` · `archive` · `restore` · `access` · `feedback` · `comment` · `settings` · `other`

- لاگ حذف یا ویرایش نمی‌شود. نگهداشت آن حداقل مطابق الزامات افتا باشد.

## ۳. قاعده‌ی دسترسی به سند (بند ۸)

تابع مرجع `evaluateAccess` در `src/km/access.ts` است و سرور باید **دقیقاً** همین منطق را پیاده کند.

```
دیدن (view):
  اگر کاربر مالک، ثبت‌کننده، تأییدکننده یا «به‌نام» در ACL باشد  ← مجاز
  در غیر این صورت هر دو شرط زیر لازم است:
      سطح اجازه دهد:
        عمومی / داخلی     → همه‌ی کاربران واردشده
        محرمانه           → مجوز knowledge.confidential
        خیلی محرمانه      → knowledge.confidential و knowledge.approve
      و (ACL خالی باشد یا یکی از ردیف‌های ACL با کاربر منطبق باشد)

دانلود (download)، فقط برای کسی که اجازه‌ی دیدن دارد:
  مالک / ثبت‌کننده                                  ← مجاز
  acl.viewOnly = true                               ← ممنوع
  accessPolicy[سطح].download = true                 ← مجاز
  ردیف منطبق ACL با download = true                 ← مجاز
  در غیر این صورت                                   ← فقط مشاهده
```

- مجوزها در **کانتکست فعلی کاربر** سنجیده می‌شوند، یعنی واحدی که کاربر در آن «ایستاده» است، و نقش‌های تخصیص‌یافته در آن واحد یا واحدهای بالاتر.
- فیلتر دامنه‌ی سازمانی (`filterScoped`) **قبل از** این قاعده اعمال می‌شود.
- **«چه کسانی می‌بینند»**: سرور endpoint زیر را بدهد که همین قاعده را روی همه‌ی کاربران دامنه اجرا کند و فهرست را با دلیل دسترسی هر نفر برگرداند:

  ```
  GET /km/docs/{id}/effective-access
  ```

  دلیل‌ها یکی از این‌هاست: مالک، تأییدکننده، نام‌برده در ACL، سطح، فهرست دسترسی.
- **«فقط مشاهده»** در سرور:
  - endpoint دانلود فایل خام را با کد ۴۰۳ رد کند.
  - پیش‌نمایش به‌صورت **تصویر صفحه‌ها با واترمارک سوخته در تصویر** تحویل داده شود. واترمارک شامل نام بیننده، تاریخ و ساعت، و کد سند است.
  - پروتوتایپ واترمارک را فقط به‌صورت لایه‌ی روی صفحه نشان می‌دهد و کپی و منوی راست‌کلیک را می‌بندد. این روش در مرورگر قابل دورزدن است و جای روش سرور را نمی‌گیرد.

## ۴. گردش کار چندمرحله‌ای (بند ۹)

### ماشین حالت

| اقدام | شرط | نتیجه |
|---|---|---|
| `submit` | `پیش‌نویس` یا `ارجاع برای اصلاح` | ← `در بررسی`. قالب بر اساس نوع سند انتخاب می‌شود و گردش کار از مرحله‌ی اول شروع می‌شود: `stepIdx=0` و `stepStartedAt=امروز` |
| `approve` روی مرحله‌ای از نوع review یا approve | کاربر بازیگر مرحله باشد | اگر این آخرین مرحله باشد، سند `منتشرشده` می‌شود. وگرنه `stepIdx` یکی جلو می‌رود و وضعیت سند `تأییدشده` می‌شود اگر مرحله‌ی بعد از نوع publish باشد، و در غیر این صورت `در بررسی` می‌ماند |
| `publish` (یا `approve` روی مرحله‌ای از نوع publish) | وضعیت `تأییدشده` | ← `منتشرشده` |
| `return` | هر مرحله | ← `ارجاع برای اصلاح`. با ارسال دوباره، گردش کار از مرحله‌ی اول شروع می‌شود |
| `archive` | — | ← `آرشیو`. ثبت دلیل الزامی است |
| `restore` | **مجوز `knowledge.archive` و ثبت دلیل الزامی است** | ← `منتشرشده` |
| نسخه‌ی جدید | اگر گردش کار روشن باشد | ← `در بررسی` و گردش کار از مرحله‌ی اول |

### بازیگران هر مرحله (`resolveApprover` و `stepActors`)

| نوع تأییدکننده | بازیگر |
|---|---|
| `user` | همان کاربر |
| `role` | همه‌ی دارندگان تخصیص معتبر آن نقش |
| `scopeManager` | نزدیک‌ترین کاربری که در واحد سند یا والدهای آن نقش مدیریتی دارد (`isAdminRole`) |
| `owner` | مالک سند |

علاوه بر این افراد:
- **جانشین ثابت** مرحله (`substitute`)
- **جانشین موقت** (`KDelegation`) که بازه‌ی جانشینی‌اش هنوز تمام نشده است
- برای سازگاری با نسخه‌ی قبل: فهرست `approvers` سند و دارندگان مجوز `knowledge.approve`

هر وقت جانشین تأیید کند، `onBehalfOf` در رویداد ثبت می‌شود.

### مهلت (SLA)

- موعد هر مرحله برابر است با `stepStartedAt + slaDays`.
- اگر امروز از موعد بگذرد، مرحله معوق است. در این حالت زمان‌بند یک بار رویداد `KM_STEP_OVERDUE` را برای بازیگران و جانشین‌ها و رویداد `KM_STEP_ESCALATED` را برای مالک سند صادر می‌کند. یک رویداد `remind` هم به تاریخچه‌ی گردش کار سند اضافه می‌شود.

## ۵. جستجو (بند ۷)

### نرمال‌سازی

نرمال‌سازی هم روی **نمایه** و هم روی **پرسش** اعمال شود (`normalizeFa` در `src/km/text.ts`):

| ورودی | خروجی |
|---|---|
| `ي` و `ى` و `ئ` | `ی` |
| `ك` | `ک` |
| `ة` و `ۀ` | `ه` |
| `أ` و `إ` و `ٱ` | `ا` |
| `ؤ` | `و` |
| اعراب، تنوین، تشدید، سکون، الف خنجری و کشیده (`ـ`) | حذف |
| نیم‌فاصله (ZWNJ)، ZWJ، فاصله‌ی نشکن و نویسه‌های جهت | فاصله |
| فاصله‌های پشت‌سرهم | یک فاصله |
| ارقام فارسی و عربی | ارقام لاتین |
| حروف لاتین | حروف کوچک |

### فیلدهای نمایه و وزن رتبه‌بندی

| فیلد | وزن |
|---|---|
| عنوان و کد | ۳ |
| برچسب | ۲ |
| توضیح، مالک و واحد | ۱ |
| متن مقاله (Markdown به متن ساده) | ۱ |
| متن استخراج‌شده‌ی هر فایل، با شماره‌ی صفحه | ۱ |

- اسناد منتشرشده یک امتیاز اضافه می‌گیرند.
- در پیاده‌سازی سرور: Elasticsearch یا OpenSearch با analyzer فارسی و همین char_filterها.

### خروجی جستجو

- برای هر نتیجه:
  - قطعه‌ی متن (snippet) با بازه‌های تطبیق برای `<mark>`
  - محل تطبیق، یعنی «فایل X — صفحه‌ی ۲»
- برای فیلترها (facet): شمارش هر مقدار نوع، واحد، وضعیت، سطح دسترسی و برچسب، با اعمال بقیه‌ی فیلترها.
- **دسترسی پیش از شمارش اعمال شود.** سندی که کاربر نمی‌بیند نباید در شمارش هم دیده شود.
- هر جستجو در `searches` ثبت می‌شود. جستجوهای بی‌نتیجه مبنای تحلیل «کمبود دانش» هستند (بند ۱۹).

## ۶. پیش‌نمایش در مرورگر (بند ۲۷)

- **PDF و Word**: تصویر صفحه‌ها، به‌همراه متن صفحه برای برجسته‌سازی نتیجه‌ی جستجو.
- **تصویر**: نمایش مستقیم.
- **ویدئو**: پخش جریانی، بخش‌ها از روی فصل‌بندی.
- **Excel**: برگه‌ها به‌صورت جدول.
- پیمایش بین صفحه‌ها و شروع از صفحه‌ی مشخص با پارامتر `?page=` پشتیبانی شود.
- هر بار که پیش‌نمایش باز می‌شود، رویداد `KM_FILE_PREVIEWED` با نام فایل ثبت شود.

## ۷. لاگ ممیزی (بند ۸، ۱۱ و ۲۷)

صفحه‌ی «لاگ ممیزی» در منوی مدیریت دانش:

- فیلترها: کاربر، نوع اقدام، سند (عنوان یا شناسه)، سطح دسترسی و بازه‌ی تاریخ
- خروجی CSV با BOM تا فارسی در اکسل درست نمایش داده شود
- در هر سند، تب «دسترسی ← تاریخچه‌ی دسترسی» که فقط مالک و راهبر آن را می‌بینند

مجوز پیشنهادی جدید: `knowledge.audit`. تا وقتی این مجوز به کاتالوگ اضافه نشده، دارندگان `knowledge.settings` یا `knowledge.reports` صفحه را می‌بینند.

## ۹. Endpointهای پیشنهادی

```
GET    /km/docs?q=&type=&unit=&status=&access=&tag=&inContent=1&page=     جستجو + facet + snippet
POST   /km/docs                                     ایجاد (فایل یا مقاله)
PATCH  /km/docs/{id}                                ویرایش فراداده (تغییر approvers → KM_APPROVER_ASSIGNED)
POST   /km/docs/{id}/versions                       نسخه‌ی جدید (multipart برای فایل یا body برای مقاله)
GET    /km/docs/{id}/versions/{a}/diff/{b}          مقایسه‌ی متنی
PUT    /km/docs/{id}/acl                            فهرست دسترسی
GET    /km/docs/{id}/effective-access               «چه کسانی می‌بینند»
GET    /km/docs/{id}/files/{fileId}/preview?page=   تصویر صفحه با واترمارک (لاگ: preview)
GET    /km/docs/{id}/files/{fileId}/download        فایل خام (لاگ: download؛ در حالت فقط‌مشاهده ۴۰۳)
POST   /km/docs/{id}/workflow                       {action: submit|approve|return|publish|archive, note}
POST   /km/docs/{id}/restore                        {reason}   — نیازمند knowledge.archive
GET    /km/workflow/inbox?view=mine|sent|overdue    کارتابل
GET    /km/workflow/templates · PUT /km/workflow/templates/{id} · DELETE …
GET    /km/delegations · POST · DELETE
GET    /km/audit?actor=&code=&entity=&access=&from=&to=&format=csv
GET    /km/saved-searches · POST · PATCH {notify} · DELETE
PUT    /km/settings/access-policy/{level}
```

## ۱۰. مجوزها

**مجوزهای موجود** (گروه «مدیریت دانش» در `permissionCatalog`):

```
knowledge.list · upload · edit · delete · categories · visibility · approve · archive · confidential
registry · rnd · processes · experiences · experts · glossary · reports · settings
```

**مجوزهای پیشنهادی جدید:**

| مجوز | کاربرد |
|---|---|
| `knowledge.download` | دانلود اسناد سطح‌هایی که سیاستشان «فقط مشاهده» است. جایگزین تیک دانلود در ACL برای نقش‌ها می‌شود |
| `knowledge.audit` | دیدن لاگ ممیزی دانش |

پروتوتایپ تا اضافه شدن `knowledge.audit` از `knowledge.settings` یا `knowledge.reports` استفاده می‌کند.

## ۱۱. مهاجرت

- سندی که `format` ندارد، `file` در نظر گرفته می‌شود.
- سندی که `acl` ندارد، فقط تابع قاعده‌ی سطح دسترسی است.
- سند `در بررسی` که `flow` ندارد، گردش کار قدیمی را ادامه می‌دهد: هر تأییدکننده‌ی سند یا دارنده‌ی `knowledge.approve` می‌تواند آن را تأیید کند. با ارسال دوباره، به قالب جدید منتقل می‌شود.
- تنظیم قدیمی `workflowSteps.review` همچنان تعیین می‌کند که آیا سند جدید یا نسخه‌ی جدید وارد گردش کار شود.

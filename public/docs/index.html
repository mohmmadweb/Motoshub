Motoshub API Documentation

The complete HTTP API of the Motoshub enterprise social network — authentication, users, feed, groups, chat, events, forum, media and more. Generated directly from the backend source annotations, organized for front-end consumption.

Interactive API Reference → Download openapi.json

1 · Quick start

Every endpoint is an HTTP POST with multipart/form-data (or application/x-www-form-urlencoded) fields, served by the gateway under two route families:

POST /mobile/services/information/{type}   # read operations
POST /mobile/services/action/{type}        # write operations

Log in once, keep the returned token, then send it as the access_token field with every authenticated call:

# 1) Log in
curl -X POST "$BASE/mobile/services/action/login" \
  -F "username=jdoe" -F "password=secret"
# → {"login": {"valid": true, "cookies": {"ow_login": "<TOKEN>"}, ...}}

# 2) Authenticated call — dashboard feed
curl -X POST "$BASE/mobile/services/information/get_dashboard" \
  -F "access_token=<TOKEN>"

# 3) Write call — publish a post
curl -X POST "$BASE/mobile/services/action/send_post" \
  -F "access_token=<TOKEN>" -F "status=Hello Motoshub!"

2 · Conventions

Request

  • Always POST; the operation name lives in the URL path ({type}).
  • Parameters are plain form fields; files use the file field (see upload_single_file).
  • Send access_token for every authenticated operation. Missing/expired tokens yield authorization_error.
  • Browser clients must send the X-Requested-With: XMLHttpRequest header.

Response

  • Always JSON. The payload is keyed by the operation name: {"send_post": {...}}.
  • Write operations include "valid": true|false and a message code on failure (e.g. input_error, authorization_error).
  • Lists are returned in stable, ready-to-render shape (the mobile apps consume the same payloads).

Roadmap note. A REST-style facade (/api/v1/social/…) over these same services is planned; operation names and payloads documented here will remain the source of truth, so integrating against the gateway today is forward-compatible.
